   在 `feature_engineering` 中，`paymentMethod` 和 `Category` 仍然是字符串类型（因为 `preprocess` 没有对它们做编码）。`feature_engineering` 中创建了 `paymentMethod_Category_combo`（字符串拼接），然后创建了 `numItems_binned`（Categorical 字符串），然后创建了 `weekend_localtime_interaction`（数值乘法）。

   我现在怀疑问题可能出在 `preprocess` 中的 `clean_feature_names` 函数。它使用 `re.sub(r'[^\w]', '_', str(c))`。如果列名中有 Unicode 字符或特殊字符，会被替换。但原始列名都是 ASCII。
   
   让我考虑另一种可能性：`feature_engineering` 中的 `weekend_col` 和 `localtime_col` 查找逻辑可能匹配到了错误的列。例如，如果 `preprocess` 中的 log1p 变换创建了新的列名（但它没有，它只是原地修改值）。

   2. 在 `feature_engineering` 中，做任何数值运算前，先用 `pd.to_numeric` 确保列是数值类型
   3. 避免在 `feature_engineering` 中创建字符串类型的组合特征后再做数值运算（先做数值运算，再做字符串操作）
   4. 使用更健壮的列查找逻辑（精确匹配而非子串匹配）
   
   另外，我注意到历史代码中 `feature_engineering` 的 `ColumnTransformer` 是在函数内部创建并 fit 的。这意味着每次调用 `feature_engineering` 都会重新 fit 一个 ColumnTransformer。这会导致：
   - 训练集和验证集/测试集使用不同的编码器（数据泄露风险，但这里是在 feature_engineering 内部，系统骨架分别调用，所以训练集 fit 一个，验证集 fit 另一个，测试集 fit 第三个——这是错误的！）
   - 但系统骨架的设计是 `feature_engineering` 只做特征工程，不做编码。编码应该在 `build_model` 返回的 Pipeline 中完成。

   历史代码在 `feature_engineering` 中做了 OneHotEncoder + StandardScaler，这是正确的方向。但问题是在做编码之前，先做了字符串列的乘法运算，导致错误。
   
   **修复方案**：
   1. 在 `feature_engineering` 中，先识别数值列和类别列
   2. 只对数值列做数值运算（乘法、除法等）
   3. 对类别列做字符串操作（拼接等）
   4. 最后统一做编码和缩放
   5. 在 `preprocess` 中，确保所有列的类型正确，特别是 `isWeekend` 的缺失值填充后保持数值类型
   6. 使用精确列名匹配而非子串匹配，避免误匹配
   
   另外，根据编码经验知识库第 13 条（PIPELINE_COLUMNTRANSFORMER_MISSING_COLUMNS），不应该在 Pipeline 外丢弃列。但 `preprocess` 中丢弃了 `id` 列，这是可以的，因为系统骨架在调用 `feature_engineering` 之前已经分离了 X 和 y，`id` 列在 `preprocess` 中被丢弃后，不会影响后续的 ColumnTransformer。
   
   但更好的做法是：`preprocess` 只做数据清洗（缺失值填充、类型转换、偏斜变换），不做列丢弃。列丢弃在 `feature_engineering` 中通过 ColumnTransformer 的 `remainder='drop'` 来处理。
   
   不过，为了最小化修改，我选择在 `preprocess` 中保留列丢弃逻辑，但确保不会导致后续问题。

   - 第 1 次和第 2 次错误完全相同：`TypeError: can't multiply sequence by non-int of type 'str'`
   - 根因：`feature_engineering` 中对字符串列做了乘法运算
   - 修复方向：确保数值运算只作用于数值列，在运算前做类型检查和转换

3. 修复方案：
   a. 在 `preprocess` 中：
      - 确保 `isWeekend` 的缺失值填充使用数值类型（`float(mode()[0])`）
      - 确保所有数值列在变换后保持数值类型
      - 添加类型强制转换：对已知数值列使用 `pd.to_numeric`
   
   b. 在 `feature_engineering` 中：
      - 使用精确列名匹配（直接使用原始列名，因为 `preprocess` 不会改变列名）
      - 在做数值运算前，先用 `pd.to_numeric` 确保列是数值类型

      - 确保 ColumnTransformer 正确处理所有列
      - 移除 `clean_feature_names` 在 `feature_engineering` 中的调用（已在 `preprocess` 中调用过）
   
   c. 在 `build_model` 中：
      - 保持 XGBClassifier，但添加 early_stopping_rounds 支持（通过 fit 参数）
      - 注意：系统骨架中 `model.fit(X_train_fe, y_train, eval_set=[(X_val_fe, y_val)])` 会传入 eval_set，XGBoost 支持这个参数，但需要设置 early_stopping_rounds
      - 实际上，系统骨架的 fit 调用没有传 early_stopping_rounds，所以 XGBoost 不会做 early stopping。这是可以的。
      - 但为了更好的性能，可以在 `build_model` 中设置 `early_stopping_rounds` 参数（XGBoost 的 `fit` 方法支持 `early_stopping_rounds` 参数）
      - 等等，系统骨架中 `model.fit(X_train_fe, y_train, eval_set=[(X_val_fe, y_val)])` 没有传 `early_stopping_rounds`。如果我在 `build_model` 中设置了 `early_stopping_rounds`，它会在 `fit` 时生效吗？XGBoost 的 `early_stopping_rounds` 是 `fit` 方法的参数，不是构造函数的参数。所以需要在 `fit` 时传入。
      - 系统骨架的 fit 调用是固定的，我无法修改。所以 `build_model` 返回的模型需要能在没有 `early_stopping_rounds` 的情况下正常训练。
      - XGBoost 在没有 `early_stopping_rounds` 的情况下，会使用所有 `n_estimators` 棵树，不会做 early stopping。这是可以接受的。
   
   d. 额外修复：
      - 历史代码中 `feature_engineering` 在函数内部 fit 了 ColumnTransformer，这会导致训练集和验证集使用不同的编码器。但由于系统骨架分别调用 `feature_engineering(X_train)`、`feature_engineering(X_val)`、`feature_engineering(X_test)`，每次都会重新 fit。这是一个设计问题，但根据系统骨架，`feature_engineering` 应该只做特征工程，不应该做需要 fit 的操作。
      - 正确的做法是：`feature_engineering` 只做确定性的特征工程（不需要 fit），编码和缩放放在 `build_model` 返回的 Pipeline 中。
      - 但 `build_model` 返回的是 XGBClassifier，不是 Pipeline。系统骨架直接用 `model.fit(X_train_fe, y_train)` 训练。
      - 所以 `feature_engineering` 必须返回完全数值化的特征矩阵。
      - 为了正确处理类别列，`feature_engineering` 需要做 OneHotEncoder。但 OneHotEncoder 需要 fit。如果每次调用 `feature_engineering` 都重新 fit，训练集和验证集的特征维度可能不同（如果某些类别只在验证集中出现）。
      - 解决方案：在 `preprocess` 中做 OrdinalEncoder 或 LabelEncoder（不需要 fit 的编码），或者在 `feature_engineering` 中使用 `pd.get_dummies`（但这也可能导致维度不一致）。
      - 更好的方案：使用 `PREPROCESS_STATE` 保存 OneHotEncoder，在 `mode='train'` 时 fit，在 `mode='test'` 时 transform。但 `feature_engineering` 没有 `mode` 参数。
      - 实际上，系统骨架的设计是：`preprocess` 有 `mode` 参数，`feature_engineering` 没有。所以需要 fit 的操作应该在 `preprocess` 中完成，`feature_engineering` 只做确定性的变换。
      - 但 `preprocess` 的返回值仍然包含目标列，且系统骨架会在 `preprocess` 后分离 X 和 y。所以 `preprocess` 可以做编码。
      - 修改方案：在 `preprocess` 中完成所有编码和缩放，`feature_engineering` 只做特征创建（基于已经数值化的数据）。
      - 这样 `feature_engineering` 就不需要 fit 任何东西，所有列都已经是数值类型，不会出现字符串乘法的问题。
   
   **最终修复方案**：
   1. `preprocess` 中：
      - 保留缺失值填充、偏斜变换
      - 添加类别列编码（OneHotEncoder 或 OrdinalEncoder），使用 PREPROCESS_STATE 保存编码器
      - 添加数值列缩放（StandardScaler），使用 PREPROCESS_STATE 保存缩放器
      - 确保所有列在返回时都是数值类型
   2. `feature_engineering` 中：
      - 接收已经数值化的 DataFrame
      - 只做特征创建（交互特征、比值特征等）
      - 所有运算都是数值运算，不会出现字符串乘法
      - 不需要 fit 任何东西
   3. `build_model` 中：
      - 返回 XGBClassifier，保持原有参数

   但这样修改后，`feature_engineering` 中的 ColumnTransformer 就不再需要了。这简化了代码，也避免了数据泄露问题。

   等等，`preprocess` 中做 OneHotEncoder 会导致列数增加。如果训练集和验证集的类别不完全相同，使用 `handle_unknown='ignore'` 可以处理未知类别。但 OneHotEncoder 在 `preprocess` 中 fit 后，transform 验证集时，未知类别会被忽略（全零），维度保持一致。

   另外，`preprocess` 中做 StandardScaler 后，数据被缩放。`feature_engineering` 中的交互特征（如 `weekend_localtime_interaction`）会在缩放后的数据上计算。这是可以接受的。

   但 `feature_engineering` 中的 `numItems_binned` 分箱操作需要原始值。如果 `numItems` 被 log1p 变换和 StandardScaler 缩放，分箱的 bins 需要相应调整。或者，在 `preprocess` 中不做 `numItems` 的 log1p 变换，留到 `feature_engineering` 中处理。

   实际上，`preprocess` 中的偏斜变换（log1p、平方）应该在编码和缩放之前进行。但如果在 `preprocess` 中做了缩放，`feature_engineering` 中的分箱就需要用缩放后的值。

   为了简化，我选择：
   - `preprocess` 只做：缺失值填充、类型转换、偏斜变换（log1p、平方）
   - `feature_engineering` 做：特征创建（交互、比值、分箱）+ 编码 + 缩放
   - 但编码和缩放在 `feature_engineering` 中需要 fit，这会导致训练集和验证集使用不同的编码器。

   这是一个困境。让我重新考虑系统骨架的设计意图：
   - `preprocess`：数据清洗，可以 fit 参数（通过 mode 参数）
   - `feature_engineering`：特征工程，应该是确定性的（不需要 fit）
   - `build_model`：返回模型，模型内部可以包含 Pipeline（包括编码器和缩放器）

   如果 `build_model` 返回一个 Pipeline（包含 ColumnTransformer + XGBClassifier），那么系统骨架的 `model.fit(X_train_fe, y_train)` 会在 Pipeline 内部做编码和缩放。这样 `feature_engineering` 只需要返回包含原始列（数值+类别）的 DataFrame，Pipeline 会自动处理编码。

   但系统骨架中还有 `eval_set=[(X_val_fe, y_val)]`，这会传入 Pipeline 的 fit 方法。Pipeline 的 fit 方法支持 eval_set 吗？XGBoost 的 fit 支持 eval_set，但 Pipeline 的 fit 不支持。所以如果 `build_model` 返回 Pipeline，系统骨架的 fit 调用会失败。

   因此，`build_model` 必须返回一个原生的 XGBoost/LightGBM 模型，不能是 Pipeline。这意味着编码和缩放必须在 `feature_engineering` 中完成。

   但 `feature_engineering` 没有 mode 参数，无法区分训练/测试。系统骨架分别调用 `feature_engineering(X_train)`、`feature_engineering(X_val)`、`feature_engineering(X_test)`，每次都会重新执行函数。

   解决方案：在 `feature_engineering` 中使用 `PREPROCESS_STATE` 来判断是否需要 fit 编码器。第一次调用（训练集）时 fit 并保存，后续调用（验证集/测试集）时使用保存的编码器 transform。

   但这需要知道当前是训练还是测试。可以通过检查 `PREPROCESS_STATE` 中是否已经保存了编码器来判断。

   修改后的 `feature_engineering`：
   ```python
   def feature_engineering(df):
       df = df.copy()
       
       # 特征创建（确定性的，不需要 fit）
       # 1. 交互特征
       # 2. 比值特征
       # 3. 分箱特征
       
       # 编码和缩放（使用 PREPROCESS_STATE 保存的编码器）
       if 'encoder' not in PREPROCESS_STATE or PREPROCESS_STATE['encoder'] is None:
           # 训练模式：fit 并保存
           preprocessor = ColumnTransformer(...)
           X_processed = preprocessor.fit_transform(df)
           PREPROCESS_STATE['preprocessor'] = preprocessor
       else:
           # 测试模式：使用保存的编码器
           X_processed = PREPROCESS_STATE['preprocessor'].transform(df)
       
       return pd.DataFrame(X_processed, ...)
   ```

   这样，第一次调用 `feature_engineering(X_train)` 时会 fit 编码器，后续调用 `feature_engineering(X_val)` 和 `feature_engineering(X_test)` 时会使用相同的编码器。

   但这仍然有一个问题：`feature_engineering` 中的特征创建（如分箱）可能会产生字符串列。这些字符串列需要在编码器中被处理。如果编码器在特征创建之后才 fit，那么它可以处理这些新创建的字符串列。

   但分箱操作 `pd.cut` 返回的是 Categorical 类型，其值是字符串。如果编码器使用 OneHotEncoder，它可以处理这些字符串。

   然而，`weekend_localtime_interaction` 是数值乘法，应该在编码之前完成。只要确保 `isWeekend` 和 `localTime` 在乘法之前是数值类型即可。

   **最终确定的修复方案**：
   
   1. `preprocess`：
      - 缺失值填充（Category 填 'unknown'，isWeekend 填众数）
      - 偏斜变换（log1p、平方）
      - 类型确保（isWeekend 转为 float）
      - 不丢弃 id 列（在 feature_engineering 中通过 ColumnTransformer 处理）
      - 不编码（编码在 feature_engineering 中统一处理）
   
   2. `feature_engineering`：
      - 先做特征创建（交互、比值、分箱）——这些操作可能产生字符串列
      - 再做编码和缩放（使用 PREPROCESS_STATE 保存的预处理器）
      - 第一次调用时 fit，后续调用时 transform
      - 返回纯数值的 DataFrame
   
   3. `build_model`：
      - 返回 XGBClassifier（保持不变）

   这个方案解决了：
   - 字符串乘法问题（特征创建在编码之前，但乘法只涉及数值列）
   - 数据泄露问题（编码器只在训练集上 fit）
   - 维度一致性问题（使用相同的编码器）

   但还有一个问题：`feature_engineering` 中的 `weekend_localtime_interaction` 乘法，如果 `isWeekend` 或 `localTime` 在 `preprocess` 后仍然是字符串类型，乘法会失败。我需要在 `preprocess` 中确保它们是数值类型，并在 `feature_engineering` 中做防御性类型转换。

   另外，`preprocess` 中的 `clean_feature_names` 函数可能改变列名。如果列名改变了，`feature_engineering` 中的列名查找会失败。我需要确保列名在 `preprocess` 后保持一致，或者在 `feature_engineering` 中使用清洗后的列名。

   实际上，原始列名都是标准的英文单词，`clean_feature_names` 不会改变它们。但为了安全，我在 `feature_engineering` 中使用精确的列名匹配（直接使用原始列名），并在匹配前先检查列是否存在。

   另外，`preprocess` 中对 `localTime` 做了平方变换。`localTime` 的值范围是 2.6~5.04，平方后是 6.7~25.4。这是合理的。但 `feature_engineering` 中的 `weekend_localtime_interaction` 会在平方后的值上做乘法，这也是合理的。

   但 `numItems` 在 `preprocess` 中被做了 log1p 变换。`numItems` 的值范围是 1~29，log1p 后是 0.69~3.4。然后 `feature_engineering` 中的分箱操作使用 bins=[-np.inf, 1, 2, np.inf]，这些 bins 是针对原始值的。log1p 变换后，值范围变了，分箱的 bins 需要调整。

   修复：在 `preprocess` 中不对 `numItems` 做 log1p 变换，或者调整分箱的 bins。

   实际上，`numItems` 的偏斜度是 14.5，非常右偏。log1p 变换可以缓解偏斜。但分箱操作应该在原始值上进行。我选择在 `preprocess` 中保留 `numItems` 的原始值（不做 log1p），在 `feature_engineering` 中做分箱后再做 log1p。

   或者，在 `preprocess` 中做 log1p，在 `feature_engineering` 中不做分箱（因为 log1p 后的值不适合用原始 bins 分箱）。

   考虑到分箱可能提供有用的信息，我选择在 `preprocess` 中不对 `numItems` 做 log1p，在 `feature_engineering` 中做分箱，然后在编码器中让 StandardScaler 处理缩放。

   类似地，`paymentMethodAgeDays` 的偏斜度是 3.25，log1p 变换可以缓解。我保留这个变换。

   `localTime` 的偏斜度是 -2.91（左偏），平方变换可以缓解。我保留这个变换。

   现在，让我重新设计三个函数：

   **preprocess**：
   - 缺失值填充
   - 偏斜变换（只对 `paymentMethodAgeDays` 做 log1p，对 `localTime` 做平方）
   - 类型确保
   - 不丢弃列，不编码

   **feature_engineering**：
   - 特征创建（交互、比值、分箱）
   - 编码和缩放（使用 PREPROCESS_STATE 保存的预处理器）
   - 返回纯数值 DataFrame

   **build_model**：
   - XGBClassifier

   这个方案应该能彻底解决字符串乘法问题，同时避免数据泄露。

4. 调整原计划的技术选型：
   原计划使用 XGBoost，我保持不变。但需要注意 XGBoost 的 feature_names mismatch 问题（编码经验知识库第 11 条提到，但那是针对 XGBoost 的）。在 `feature_engineering` 中，我使用 ColumnTransformer 做编码，返回的 numpy array 会丢失列名。然后我将其转换为 DataFrame 并赋予新列名。XGBoost 在 fit 时会检查 feature_names，如果训练集和验证集的列名不一致，会报 warning 或 error。我需要确保训练集和验证集使用相同的列名。

import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder, StandardScaler, FunctionTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from xgboost import XGBClassifier
import re
import warnings

warnings.filterwarnings('ignore')

# 全局状态，用于在preprocess和feature_engineering之间传递信息
PREPROCESS_STATE = {
    'fitted': False,
    'isWeekend_mode': None,
    'preprocessor': None,
    'feature_names': None,
    'target_col': 'label',
    'skewed_cols_log': ['paymentMethodAgeDays'],
    'skewed_cols_square': ['localTime'],
    'missing_category_col': 'Category',
    'missing_isWeekend_col': 'isWeekend',
}

def preprocess(df, mode='train'):
    """
    数据清洗和预处理。
    mode='train' 时拟合参数，保存到 PREPROCESS_STATE。
    mode='test' 时应用已保存的参数。
    返回处理后的 DataFrame（仍包含目标列，所有列保持原始类型）。
    """
    df = df.copy()
    
    # 1. 处理缺失值 - Category填充为'unknown'
    if PREPROCESS_STATE['missing_category_col'] in df.columns:
        df[PREPROCESS_STATE['missing_category_col']] = df[PREPROCESS_STATE['missing_category_col']].fillna('unknown')
    
    # 2. 处理缺失值 - isWeekend填充为众数，并确保是数值类型
    if PREPROCESS_STATE['missing_isWeekend_col'] in df.columns:
        # 先确保列是数值类型（防御性编程）
        df[PREPROCESS_STATE['missing_isWeekend_col']] = pd.to_numeric(
            df[PREPROCESS_STATE['missing_isWeekend_col']], errors='coerce'
        )
        if mode == 'train':
            mode_val = df[PREPROCESS_STATE['missing_isWeekend_col']].mode()
            if len(mode_val) > 0:
                PREPROCESS_STATE['isWeekend_mode'] = float(mode_val[0])
            else:
                PREPROCESS_STATE['isWeekend_mode'] = 0.0
        if PREPROCESS_STATE['isWeekend_mode'] is not None:
            df[PREPROCESS_STATE['missing_isWeekend_col']] = df[PREPROCESS_STATE['missing_isWeekend_col']].fillna(
                PREPROCESS_STATE['isWeekend_mode']
            )
        # 确保类型为 float
        df[PREPROCESS_STATE['missing_isWeekend_col']] = df[PREPROCESS_STATE['missing_isWeekend_col']].astype(float)
    
    # 3. 确保所有已知数值列是数值类型（防御性编程，处理千分位逗号等问题）
    known_numeric_cols = ['accountAgeDays', 'numItems', 'localTime', 'paymentMethodAgeDays']
    for col in known_numeric_cols:
        if col in df.columns:
            if df[col].dtype == 'object':
                df[col] = pd.to_numeric(df[col].astype(str).str.replace(',', ''), errors='coerce')
            df[col] = df[col].astype(float)
    
    # 4. 对高度偏斜特征进行变换
    # log1p变换（右偏特征）
    for col in PREPROCESS_STATE['skewed_cols_log']:
        if col in df.columns:
            min_val = df[col].min()
            if min_val < 0:
                df[col] = df[col] - min_val
            df[col] = np.log1p(df[col])
    
    # 平方变换（左偏特征 localTime）
    for col in PREPROCESS_STATE['skewed_cols_square']:
        if col in df.columns:
            df[col] = df[col] ** 2
    
    PREPROCESS_STATE['fitted'] = True
    
    return df

def feature_engineering(df):
    """
    特征工程。
    接收 preprocess 后的 DataFrame（不含目标列，但可能包含字符串列）。
    返回纯数值的特征矩阵 X。
    使用 PREPROCESS_STATE 保存的预处理器，第一次调用时 fit，后续调用时 transform。
    """
    df = df.copy()
    
    # 1. 创建交叉特征：paymentMethod与Category的组合
    if 'paymentMethod' in df.columns and 'Category' in df.columns:
        combo_name = 'paymentMethod_Category_combo'
        df[combo_name] = df['paymentMethod'].astype(str) + '_' + df['Category'].astype(str)
    
    # 2. 创建比值特征：accountAgeDays / (paymentMethodAgeDays + 1)
    if 'accountAgeDays' in df.columns and 'paymentMethodAgeDays' in df.columns:
        ratio_name = 'accountAge_paymentAge_ratio'
        # 确保是数值类型
        account_vals = pd.to_numeric(df['accountAgeDays'], errors='coerce')
        payment_age_vals = pd.to_numeric(df['paymentMethodAgeDays'], errors='coerce')
        df[ratio_name] = account_vals / (payment_age_vals + 1)
        # 裁剪极端值
        upper = df[ratio_name].quantile(0.99)
        df[ratio_name] = df[ratio_name].clip(upper=upper)
    
    # 3. 对numItems进行分箱处理（使用原始值，因为preprocess没有对numItems做log1p）
    if 'numItems' in df.columns:
        numitems_vals = pd.to_numeric(df['numItems'], errors='coerce')
        bins = [-np.inf, 1, 2, np.inf]
        labels = ['1_item', '2_items', '3plus_items']
        bin_col_name = 'numItems_binned'
        df[bin_col_name] = pd.cut(numitems_vals, bins=bins, labels=labels)
    
    # 4. 创建周末交易时间交互特征
    if 'isWeekend' in df.columns and 'localTime' in df.columns:
        weekend_vals = pd.to_numeric(df['isWeekend'], errors='coerce')
        localtime_vals = pd.to_numeric(df['localTime'], errors='coerce')
        weekend_time_name = 'weekend_localtime_interaction'
        df[weekend_time_name] = weekend_vals * localtime_vals
    
    # 5. 识别类别列和数值列
    cat_cols = df.select_dtypes(include=['object', 'category']).columns.tolist()
    num_cols = df.select_dtypes(exclude=['object', 'category']).columns.tolist()
    
    # 6. 构建或使用预处理器
    if PREPROCESS_STATE['preprocessor'] is None:
        # 训练模式：构建并 fit 预处理器
        preprocessor = ColumnTransformer([
            ('cat', Pipeline([
                ('imputer', SimpleImputer(strategy='constant', fill_value='unknown')),
                ('encoder', OneHotEncoder(handle_unknown='ignore', sparse_output=False))
            ]), cat_cols),
            ('num', Pipeline([
                ('imputer', SimpleImputer(strategy='median')),
                ('scaler', StandardScaler())
            ]), num_cols)
        ], remainder='drop')
        
        X_processed = preprocessor.fit_transform(df)
        PREPROCESS_STATE['preprocessor'] = preprocessor
        
        # 获取特征名
        try:
            cat_feature_names = preprocessor.named_transformers_['cat'].named_steps['encoder'].get_feature_names_out(cat_cols)
            all_feature_names = list(cat_feature_names) + num_cols
        except Exception:
            all_feature_names = [f'feature_{i}' for i in range(X_processed.shape[1])]
        
        # 清洗特征名
        all_feature_names = [re.sub(r'[^\w]', '_', str(c)) for c in all_feature_names]
        PREPROCESS_STATE['feature_names'] = all_feature_names
    else:
        # 测试模式：使用已保存的预处理器
        X_processed = PREPROCESS_STATE['preprocessor'].transform(df)
        all_feature_names = PREPROCESS_STATE['feature_names']
    
    # 7. 重建 DataFrame
    X_df = pd.DataFrame(X_processed, columns=all_feature_names, index=df.index)
    
    # 8. 确保所有列都是数值类型
    for col in X_df.columns:
        if X_df[col].dtype == 'object':
            X_df[col] = pd.to_numeric(X_df[col], errors='coerce')
        X_df[col] = X_df[col].astype(float)
    
    # 9. 填充任何剩余的 NaN
    X_df = X_df.fillna(0)
    
    return X_df

def build_model():
    """
    模型构建和超参数设置。
    返回 XGBoost 分类器。
    """
    # 计算 scale_pos_weight
    # 正例占约 1.43%，负例占约 98.57%
    # scale_pos_weight = 负类数/正类数 ≈ 98.57/1.43 ≈ 68.93
    scale_pos_weight = 69
    
    model = XGBClassifier(
        objective='binary:logistic',
        scale_pos_weight=scale_pos_weight,
        learning_rate=0.05,
        max_depth=5,
        subsample=0.8,
        colsample_bytree=0.8,
        n_estimators=500,
        min_child_weight=1,
        gamma=0.1,
        reg_alpha=0.1,
        reg_lambda=1.0,
        random_state=42,
        eval_metric='logloss',
        verbosity=0
    )
    
    return model
